# 方法与实现边界

当前主流程由 ConditionalCoordinator 调用 CoordinatorV5。先从源三角网格构建几何特征参考，读入与源面顺序一致的方向场以及无约束基线，再根据输出缺陷生成约束与尺寸提案。

## 特征、约束、尺寸

reference_graph 和 geometric_inventory 负责组织源几何上的曲线组，使用配套 weak_layout_pipeline 的锐边、拓扑与距离辅助函数。旧顶层 structural_graph 模块不参与当前流程。候选几何特征不等于最终硬约束；源特征即使暂缓或未被选择，也保留在评价与尺寸需求中。

基线缺陷包含源特征到输出表面的偏离，以及附近输出边是否沿特征方向覆盖。当前诊断分辨率为 0.1h 和 15°，不等于 CAD 工程公差。缺陷严重的曲线组优先尝试，使用固定场/参数化状态检查一类强制塌缩的组合冲突。不使用固定50%边长或固定特征条数配额。

geometry_budget 根据全部主特征的间距与曲率估计局部尺寸，再传播尺寸渐变、估计整体数量并在预算下分配。分辨率不足可由尺寸调整部分缓解；硬等式、场或整数不相容并不一定可通过加密解决。

## 执行与停止

1. 源/基线经几何检查且无需要修复的诊断缺陷时，条件流程保留基线。
2. 否则生成初始提案；包含均匀与分配尺寸分支，以及各自至多一次数量校正。初始阶段存在可接受新候选就停止。
3. 仍无可接受提案才进入 v5 反馈：最多两个有效反馈轮次、12次逻辑尝试和12次父候选访问；尝试约束、尺寸或失败恢复。具体上限见运行写出的 policy.json。
4. 最终接受保留原合计保护，并要求基本有效性与两个对角剖分的相交/退化检查通过。失败时回退已有合格结果，源本身不合格时不生成推荐。

最终检查使用 CGAL triangle-soup 实现。它检验两种三角嵌入，不是任意双线性四边形曲面的完整证书。合计保护仍可掩盖局部逐边退步，不应解释为逐点公差保证。

## 版本关系

- coordinator.py：共享的 v4 协调框架。
- coordinator_v5.py：保护退步触发、跳过无操作父候选、严格几何检查。
- conditional_coordinator.py：按需进入/停止；仍处于开发版本。
- 文件名带 v1/v2/v3 的若干辅助模块依然被当前实现调用，发布时保留其名称和算法内容。

本次导出不改变方法参数或科学接受条件。历史结果按各自版本解释，不能把最新推荐替换旧表后沿用其数量匹配结论。
